# 原始愿景与现状差距审计

## 审计依据

本次审计同时阅读了 WPS 资料包中的 `PROJECT_PLAN.md`、`PROJECT_INTRODUCTION.md`、`SYSTEM_ARCHITECTURE.md`、`WORK_RULES.md`、`DEVELOPMENT_WORK_PLAN.md`、`HANDOVER_2026-05.md`、`error_summary.md`，以及此前被忽略的 1851 行 `project_communication.md`。

交流记录补足了主文档没有充分强调的三项原则：

1. 无限时空图首先是历史知识系统，地图只是其中一种表达工具。
2. 书库、阅读器、泛实体百科、知识图谱、地图和时间线必须互相穿透，不能成为并列孤岛。
3. “只剩数据”必须指功能与数据契约真的齐备，不能把占位页面、模拟数据或尚未实现的管线称为完成。

## 当前架构的可取之处

- 模块化单体和六边形边界正确解决了“以后加功能会不会另起一套架构”的问题。
- `KnowledgePublication` 已成为数据管线与所有公众功能之间的唯一发布边界。
- 原文、简体、白话三层分离，实体提及以原文字符偏移为准。
- 主张、时空经历、地图观测都保存或继承原文证据。
- 地图使用真正的 MapLibre GIS 引擎，存储和瓦片均位于可替换适配边界。
- 静态发布包只是首个适配器，将来换数据库、全文索引或空间服务不要求重写页面。

## 关键结论

当前仓库已经不是旧项目那种页面与数据互相硬编码的结构，领域模型和主要功能骨架可以保留。但“全部公众功能已齐备、唯一缺少数据”的表述仍不准确：数据生产与编辑面虽已形成原型，契约统一、发布安全、分层边界、自动测试和真实数据闭环尚未达到正式发布标准。当前最高优先级是执行架构迁移路线，而不是继续增加页面数量。

## 后续优先级

### P0：让真实方志可重复入库

1. 定义来源包清单、校验值、权利状态与原件定位。
2. 实现 TXT、DOCX、EPUB、文本 PDF、扫描 PDF/图片的来源适配器。
3. 实现 OCR/转录结果与原件分离、稳定分段和段落 ID 生成。
4. 将简体转换、标点整理、白话译文作为独立派生层。
5. 建立候选提取结果、人工审核记录和发布门禁。

### P1：补足历史地图与阅读深度

1. 历史名称和疆域切片随时间切换，现代底图标签只作背景参考。
2. 时间轴继续由月扩展到日级播放，并保持原纪年与公元日期并列。
3. 实现 IIIF 多页影印导航、版面区域与文本段落联动。
4. 为现有组合检索增加可替换的语义检索适配器。

### P2：地方社会与文博深化

1. 家族谱系、师承、任官、迁徙、战争、灾异、物产与赋役的专门视图。
2. 文物专家名/公众名、材质工艺、铭文、发掘与收藏流转信息框。
3. 史源引用链、矛盾规则和领域常识检查插件。

### P3：规模化基础设施

当静态发布包无法承受数据规模时，只在现有仓储端口后增加全文索引、空间数据库、PMTiles/矢量瓦片与远程 API；功能模块、领域 ID 和证据链不重写。
