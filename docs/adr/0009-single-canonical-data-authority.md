# ADR 0009：唯一规范数据权威与共享运行时

状态：已接受
日期：2026-07-16

## 背景

书库、阅读器、地图、图谱、时间线、人物和文博都会使用同一批历史事实。如果各模块维护自己的 JSON、缓存对象或数据库表并允许独立修订，实体和证据必然分叉。数据生命周期也可能被误解为多份业务真相。

## 决策

1. 任一修订只有一个 Canonical Dataset，是唯一可编辑的规范事实权威。
2. Publication 是 Canonical 的确定性、不可变版本快照，不是另一套人工维护数据。
3. 每个公众运行实例只激活一个 Publication Revision，并只创建一个共享 `DataContext`。
4. 所有功能通过同一应用服务和仓储实例读取该上下文；跨模块只使用品牌 ID 引用对应记录。
5. 搜索索引、空间索引、地图瓦片、图谱和时间线缓存是可删除、可重建的派生投影，必须携带 `publicationId`、契约版本和来源校验值。
6. 投影版本与活动发布版本不一致时必须拒绝服务，不能混用数据。
7. 原件、暂存、候选和审核决策只供生产审计，不向公众功能开放查询。

## 后果

- 功能模块不能各自加载发布包或建立持久业务仓库；
- 组合根负责唯一一次装配，服务共享同一数据上下文；
- 为性能复制的结构必须可重建且只读；
- 数据修订回到 Canonical/Decision 流程，再生成新 Publication；
- CI 检查直接数据导入、运行时版本一致性、投影来源版本和确定性发布。
