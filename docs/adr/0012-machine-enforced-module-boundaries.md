# ADR 0012：机器执行模块边界与技术债务上限

- 状态：accepted
- 日期：2026-07-16

## 背景

仅靠架构文档无法阻止页面直接读取数据、功能相互导入、adapter 承担领域规则或超大文件继续增长。当前原型已有少量超限文件，立即要求全部消失会阻塞迁移，但无上限会让债务扩大。

## 决策

在统一 `pnpm verify` 中加入 `architecture:check`，检查 workspace 依赖方向、adapter 组合根、功能隔离、契约字段命名、深层导入和文件大小。

现存超限文件登记在 `config/architecture-debt-baseline.json`，其行数只允许下降。新文件遵守业务代码 400 行、CSS 600 行硬上限。豁免变更必须有 ADR、负责人和移除期限。

## 后果

- 架构违规在本地和 CI 直接失败，不依赖评审者记忆。
- 技术债可以渐进偿还，但不能通过修改基线掩盖增长。
- 检查器是第一层防线；语义边界仍需要 contract/domain/application 测试证明。
