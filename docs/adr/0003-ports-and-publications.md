# ADR 0003：仓储端口与发布包

## 状态

已接受；应用与适配器职责由 ADR 0006 进一步收紧。

## 决定

公众功能通过 `ApplicationServices` 调用按能力划分的仓储端口；数据以版本化 `KnowledgePublication` 进入适配器。静态 JSON、数据库和远程 API 都必须实现相同端口。

## 原因

项目早期适合静态数据，规模扩大后可能需要数据库、空间索引和全文搜索。如果页面直接绑定当前存储，届时必然重写功能架构。端口把存储变化限制在适配层，同时发布包为数据管线和应用之间提供可审计边界。

## 后果

- 页面不得直接导入数据文件或数据库客户端。
- 新存储需要实现仓储端口，但不修改功能模块。
- 契约版本不匹配时适配器必须拒绝加载，而不是静默猜测。
