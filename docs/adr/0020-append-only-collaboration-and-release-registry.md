# ADR 0020：追加式协作包与发布登记簿

- 状态：已接受
- 日期：2026-07-20

## 背景

现有工作台能在单机保存和导出决策，管线能原子生成并验证一个发布包，但多人决策合并、冲突识别、
多版本登记、并发激活和可审计回滚尚无统一协议。

## 决策

1. 三类审核共享版本绑定 `DecisionBundle` envelope，内部继续使用现有决策类型。
2. 只在实质结果相同的情况下自动合并；审核人和时间差异保留在合并审计报告中。
3. 实质结果冲突必须人工裁决，禁止最后写入获胜。
4. 协作包不含候选原文或正式事实，不直接修改发布包。
5. 发布登记簿把不可变 `releases` 与追加式 `activations` 分开。
6. 登记必须通过发布门禁且校验身份一致；激活必须提供预期当前校验和。
7. 回滚以新激活事件完成，不删除、不覆盖发布历史。

## 后果

- 本地文件、Git 审核或未来服务端协作都使用同一协议。
- 多人意见冲突可见、可复核，不因导入顺序丢失。
- 数据版本可登记、切换和回滚，完整历史仍可审计。
- 协作包与发布登记簿是流程制品，不加入 `KnowledgePublication`，因此不制造第二事实模型。

## 被拒绝的方案

- 工作台直接写共享数据库中的 Canonical。
- 按导入时间或审核人等级自动覆盖冲突。
- 用可变 `current.json` 作为唯一发布历史。
- 回滚时删除新版本或改写旧发布包。
