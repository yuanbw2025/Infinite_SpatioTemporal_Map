# ADR 0018：来源谱系与研究规则注册表

- 状态：已接受
- 日期：2026-07-20

## 背景

项目已有统一 `SourceRecord`、段落证据和四类研究检查，但无法表达来源之间的引用、派生、版本和数字化关系；
研究检查也集中在一个函数中，无法在不修改核心用例的情况下增加可解释规则。

## 决策

1. 在 0.8 契约中加入 `sourceRelations`，它只引用现有 `SourceRecord`，不建立第二套来源实体。
2. `SourceRelation` 使用受控、有方向的 `relationType`，必须有至少一个 `SourceRef` 作为关系依据。
3. 管线强制检查引用完整性、自环和重复边；所有关系参与发布包校验和。
4. 应用层提供来源链查询投影，UI 不直接遍历原始集合。
5. 研究检查拆成稳定 ID 的内置规则注册表。
6. 可选 `ResearchRulePort` 只读当前发布包并返回 `ResearchFinding`；应用层验证插件结果后统一合并。
7. 每条研究线索公开 `ruleId`，机器提示不写回正式史实。

## 后果

- 来源版本史、数字化谱系和参考关系可追踪且可审核。
- 增加研究规则不需要复制研究页或另建数据通道。
- 契约由 0.7 升至 0.8，迁移器为旧发布包添加空 `sourceRelations`。
- 外部规则拥有读取完整发布包的能力，因此只能加载可信实现；边界校验保证其输出不会引用不存在的记录。

## 被拒绝的方案

- 用普通实体关系表示来源链：混淆史实实体与书目对象。
- 只从作品、版本的 `sourceRefs` 临时反推谱系：无法表达方向、关系类型和审核依据。
- 让插件返回任意 JSON 或直接修改发布包：破坏统一契约和不可变发布原则。
